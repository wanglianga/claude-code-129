# 社区舞蹈队 · 排练报名与演出走位协作平台

基于 **React + TypeScript + Zustand + Vite** 的单页应用。队长、队员、服装负责人、文化站、音响师、志愿者六个角色，在同一份演出记录中完成「报名 → 排练 → 走位 → 服装 → 演出审核 → 现场签到」全流程协作。数据通过 zustand persist 保存在浏览器 localStorage，可随时用页头「↺ 重置数据」恢复演示初始数据。

## 本地启动

```bash
npm install        # 若 npm 缓存目录无权限，加 --cache /tmp/npm-cache
npm run dev        # 开发服务器，默认 http://localhost:5173
```

其他命令：

```bash
npm run build      # tsc --noEmit 类型检查 + vite 生产构建（输出 dist/）
npm run preview    # 预览生产构建
```

## 测试账号（角色）

无登录流程，页面右上角「当前身份」下拉框即测即换，共 6 个角色：

| 角色 | 主要操作入口 |
| --- | --- |
| 队长 | 发布报名（报名页）、平板签到/曲目版本/动作分段/重点成员（排练签到页）、走位编排与缺席补位（走位编排页） |
| 队员 | 查看排练安排、曲目版本更新、健康提醒与通知 |
| 服装负责人 | 服装页：发放（本人/家属代领）、尺码调换、押金、归还 |
| 文化站 | 文化站页：场地审批/驳回/缩小、节目审查/要求调整、海选评分、全流程连续性监督 |
| 音响师 | 演出日页查看各节目音响需求与最新曲目版本 |
| 志愿者 | 演出日页查看候场顺序与引导分工 |

预置演示数据：夕阳红广场舞队（10 人，《红红火火迎国庆》排练中 + 已归档的《春天的故事》）、金秋民族舞队（6 人，《草原情》海选待审、《丰收锣鼓》待演出），含签到、队形、服装、通知、排练室占用等完整种子数据。

## 功能与验证方式（本题验证路径）

启动 `npm run dev` 后可按以下路径逐项验证：

1. **报名**：报名页 → 队长发布新节目（含类型/主题/时长/音响需求/是否海选）；队员报名表记录年龄、联系方式、服装尺码、可排练时间、是否参加正式演出、身体注意事项。
2. **排练签到（平板）**：排练签到页 → 大按钮签到（出席/请假/缺席）；60 岁以上或有身体注意事项的队员自动进入「健康提醒」横幅；可上传曲目版本（自动通知队员与音响师）、维护动作分段、标记重点练习成员。
3. **缺席影响站位**：将前排队员「张淑英」标记为请假 → 队长通知栏收到紧急提醒；走位编排页红色列出受影响站位（前排高亮），并给出「上次出席且未站位」的补位人选；点人名再点网格即完成补位，调整记录留痕。
4. **场地缩小**：文化站页对《红红火火迎国庆》点「场地缩小」→ 队长收到紧急通知；走位页出现容量告警，可用「−一排/−一列」压缩队形，被移出队员记入调整记录。
5. **节目内容调整**：文化站页「要求调整」填写意见 → 节目状态变为「要求调整」并通知队长。
6. **服装**：服装页 → 发放（本人或家属代领，代领自动通知队长）、登记「尺码不合适」→ 调换 → 换发完成、收押金、演出后登记归还。
7. **文化站连续性**：文化站页下半部分查看每个节目「报名→排练→走位→服装→演出审核→现场签到」六环节时间线，断档会标红「流程跳跃」。
8. **海选**：文化站页对《草原情》评分并决定是否入围，结果通知队长。
9. **排练室共用**：排练室页两支队伍分时段共用排练室 A/B，冲突时段无法重复预约。
10. **演出日**：演出日页调整候场顺序（↑↓）、指派志愿者引导、节目「上场/完成」、逐人现场签到（缺人时提示队长核对站位）、发布现场临时通知（全员横幅可见）。
11. **演出档案**：演出完成的节目在演出日页点「完成」→ 档案页「归档并通知」发布下次活动通知；档案保留签到汇总、服装归还、走位调整记录、现场照片。

## 已执行的验证结论

以下验证在本工作区实际执行并通过：

- `npm install --cache /tmp/npm-cache`：依赖安装成功（首次因默认 npm 缓存目录权限失败，改用本地缓存目录后成功）。
- `npm run build`（= `tsc --noEmit && vite build`）：TypeScript 严格模式类型检查通过，Vite 生产构建成功（60 个模块，产物约 216 KB JS / 10 KB CSS）。
- `npm run dev` 冒烟测试：开发服务器启动后，`/`、`/src/main.tsx`、`/src/App.tsx`、`/src/store.ts`、`/src/pages/FormationPage.tsx`、`/src/pages/StationPage.tsx` 均返回 HTTP 200，dev 日志无报错。

未覆盖项：未编写自动化单元测试，界面交互请按上方「功能与验证方式」人工逐项验证。

## 目录结构

```
src/
  types.ts            数据模型（队员/节目/排练/队形/服装/通知/预约/照片）
  seed.ts             演示种子数据
  store.ts            Zustand store：全部协作动作（含自动联动通知）
  utils.ts            缺席影响分析、流程连续性、健康关注等派生逻辑
  App.tsx             页头（角色切换/通知/重置）+ 九个标签页
  components/         通知抽屉、节目选择器
  pages/              总览/报名/排练签到/走位编排/服装/文化站/排练室/演出日/演出档案
```
